# SENTINEL — SOC Console

A fully self-contained, single-page **Security Operations Center dashboard** built with plain HTML, CSS, and vanilla JavaScript. No build tools, no frameworks, no server, no installation — you open `index.html` and it runs.

> ⚠️ **Safety note:** Every event, IP score, hash verdict, and log finding you see is generated by a **local simulator or a static offline heuristic**. Nothing in this project performs real network scanning, exploitation, or unauthorized access. The only code that talks to the internet is in the clearly-labeled "Optional live lookup" sections, and it only calls public, read-only threat-intelligence APIs using a key **you** provide.

---

## 1. Create the folder

Create a new folder anywhere on your computer, e.g. `SENTINEL-SOC`, and make sure it contains these four files, all in the **same folder** (not in subfolders):

```
SENTINEL-SOC/
├── index.html
├── style.css
├── script.js
└── README.md
```

## 2. Where to paste each file

- Paste the **HTML** code into a file named exactly `index.html`
- Paste the **CSS** code into a file named exactly `style.css`
- Paste the **JavaScript** code into a file named exactly `script.js`
- Paste this file into `README.md` (optional — just documentation)

The filenames must match exactly (lowercase, correct extensions) because `index.html` links to the other two by name.

## 3. How to start it

Just **double-click `index.html`**. It opens in your default browser and starts running immediately — live feed, clock, charts, and everything else start automatically. There is nothing to install and no terminal command required.

Works in any modern browser (Chrome, Edge, Firefox, Safari). For the best experience use a recent version — the dashboard uses standard `<canvas>` charts and the Web Audio API for alert sounds, both of which are supported everywhere modern.

## 4. What you should see immediately

The moment the page loads:

- The **live clock** in the top-right starts ticking every second.
- A **"LIVE"** badge with a pulsing dot appears next to the logo.
- The **event feed** is pre-seeded with ~24 recent events, and a **new simulated security event appears every 2–5 seconds** automatically — no refresh needed.
- **KPI counters** (Critical / High / Medium / Low·Info / Total / Open incidents) update in real time as events arrive, with a brief highlight flash on change.
- The **event volume chart** redraws every second on a rolling 60-second window; the **severity distribution chart** updates whenever counts change.
- The **system status panel** shows 8 simulated services (firewall, IDS/IPS, SIEM collector, endpoint agents, etc.) that occasionally flicker between Operational / Degraded / Down, like real infrastructure monitoring.
- Whenever a **Critical or High** severity event fires, a **toast notification** slides in top-right and a short alert tone plays (mute with the speaker icon in the header). Critical events also pulse the bell icon and bump its counter badge.
- Two **sample incidents** are pre-loaded in the Incidents tab so it isn't empty on first load.

## How the analyzers work (and their limits)

All five analysis tools (IP, URL, Email, Hash, Log) run **entirely in your browser** using deterministic, offline heuristics:

- **IP Investigation** — scores an IPv4 address using a seeded pseudo-random model (the same IP always gets the same score), plus a small built-in list of "known bad" sample IPs, simulated geolocation/ASN, and any matching events from the live feed.
- **URL Analyzer** — parses the URL and checks structural red flags: raw-IP hosts, missing HTTPS, punycode, excessive hyphens/subdomains, suspicious TLDs, brand-keyword mismatches, shorteners, and credential-harvesting-style paths.
- **Email Analyzer** — parses pasted headers/body for display-name vs. domain mismatches, Reply-To mismatches, urgency language, shortened/mismatched links, generic greetings, risky attachment extensions, and SPF/DKIM/DMARC failure mentions.
- **Hash Analyzer** — checks MD5/SHA-1/SHA-256 hashes against a small local sample "known-bad" list, falling back to a seeded pseudo-random verdict for anything else, so results are consistent across repeat lookups.
- **Log Analyzer** — regex-matches pasted log lines for brute-force patterns, SQL injection, XSS, path traversal, known scanner tool signatures, and suspicious shell commands.

These are **teaching-grade heuristics for a simulated environment**, not a production threat-intel engine — they're intentionally transparent so you can read exactly how each score is produced in `script.js`.

## Optional: connecting real threat-intelligence APIs

Three of the analyzer tabs (IP, URL, Hash) have an **"Optional live lookup"** section, clearly separated in both the HTML and `script.js` (see the `LiveAPI` object) from the offline simulator above it:

- **IP Investigation** → [AbuseIPDB](https://www.abuseipdb.com/) — needs a free API key.
- **URL Analyzer** → [Google Safe Browsing](https://developers.google.com/safe-browsing) — needs an API key.
- **Hash Analyzer** → [VirusTotal](https://www.virustotal.com/) — needs an API key.

To use these, paste your own key into the password field in that section and click "Check live reputation." Notes:

- **The dashboard is fully functional without any of these keys.** They're additive.
- These calls go **directly from your browser** to the provider. Some providers block direct browser requests (CORS), in which case the call will fail with a clear inline message — that's expected behavior, not a bug, and is explained in the UI.
- Your API key is only ever stored in the page's memory for the current session (typed into a password field) — it is never saved to disk, sent anywhere else, or included in exported reports.

## Data persistence

This is a front-end-only demo: all events, incidents, and settings live in memory for the current browser tab/session. Reloading the page resets the simulation and re-seeds fresh sample data. Use **Export report** any time you want to save a JSON snapshot of the current state.

## File overview

- `index.html` — page structure: header, sidebar navigation, six tool tabs, toast container, and the incident modal.
- `style.css` — a dark SOC-console visual theme (design tokens at the top of the file), fully responsive down to mobile.
- `script.js` — everything else: the event simulator, canvas charts, feed/filtering, all five analyzers, incident management, notifications/sound, JSON export, and the optional `LiveAPI` integration layer.
